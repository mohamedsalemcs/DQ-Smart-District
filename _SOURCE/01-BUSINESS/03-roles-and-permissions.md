# الأدوار والصلاحيات — Roles & Permissions

`BA` · محلل الأعمال · v1.0

> ### ⚠️ نتيجة التدقيق الأولى
> **النظام الحالي لا يملك طبقة صلاحيات إطلاقًا.** `currentUsers` يربط الشخصية بشخص واحد ثابت، وكل إجراء متاح لكل من يفتح الشاشة. لا يوجد فحص واحد للدور في 11,278 سطرًا.
> النتيجة العملية: **أي مستخدم في بوابة الإدارة يستطيع إيقاف مركبة**، والكود يُسند القرار زورًا إلى «أول مشرف في القائمة» عبر `s.people.find(p => p.role === 'supervisor')!` — لا إلى الفاعل الحقيقي. راجع `DEF-006`.
> هذا المستند يعرّف النموذج الصحيح، ويحدد ما نُفّذ منه في هذه النسخة وما بقي موثّقًا للمرحلة التالية.

---

## 1. التسلسل: شخصية ← دور ← صلاحية

النظام يميّز ثلاثة مستويات، وخلط الكود الحالي بينها هو مصدر العيب:

| المستوى | ما هو | مثال | يحدد |
|---|---|---|---|
| **الشخصية** (Persona) | البوابة/السطح الذي تدخل منه | `security` | التخطيط، الثيم، التنقل |
| **الدور** (Role) | صفتك الوظيفية | `supervisor` | ما يُسمح لك بفعله |
| **الصلاحية** (Permission) | إجراء ذرّي واحد | `violation.suspend_vehicle` | التحقق الفعلي عند الإجراء |

**القاعدة `BR-040`:** الشخصية تحدد ما **تراه**. الدور يحدد ما **تفعله**. لا يجوز أبدًا استنتاج الصلاحية من الشخصية.

## 2. كتالوج الأدوار

عشرة أدوار معرّفة في [`src/types/index.ts:12`](../../src/types/index.ts#L12). كل دور ينتمي لشخصية أساسية:

| الدور | العربية | الشخصية | الوصف التشغيلي |
|---|---|---|---|
| `owner` | مالك | resident | يملك الوحدة. أعلى صلاحية على ملف عقاره. |
| `tenant` | مستأجر | resident | يشغل الوحدة. صلاحيات المالك ناقصة نقل الملكية. |
| `resident` | مقيم | resident | فرد عائلة مرتبط بالوحدة. يقرأ ويبلّغ، لا يفوّض. |
| `company_rep` | ممثل شركة | resident | يمثل منشأة تجارية. تصاريح عمالة وخدمة بالجملة. |
| `embassy_rep` | ممثل سفارة | resident | يدير مواعيد سفارته وحدها اليومي. |
| `guard` | حارس أمن | security | ينفّذ عند البوابة. **يسجّل ولا يقرّر.** |
| `supervisor` | مشرف أمن | security | يقرّر: الإيقاف، اعتماد المحضر، التصعيد. |
| `admin_staff` | موظف إدارة | admin | يصرّف الطوابير: تصنيف، إسناد، اعتماد تصاريح. |
| `inspector` | مفتش | admin | يسجّل المخالفات ميدانيًا. لا يصعّد ولا يوقف. |
| `driver` | سائق | — | كيان موصوف لا مستخدم. لا يدخل النظام. |

> **ثغرة أعمال `GAP-03`:** لا يوجد دور `district_manager` (مدير الحي) — الشخص الذي يعدّل سلّم التصعيد وSLA وقواعد العمل. حاليًا شاشة `الإعدادات` مفتوحة لأي `admin_staff`، أي أن موظف إدخال بيانات يستطيع تغيير درجة إيقاف المركبات لكل الحي. **أُضيف الدور في هذا المستند وقُيّدت الشاشة.**

> **`BR-045` — قاعدة الإيقاف:** إيقاف مركبة ورفعه **قرار مشرف حصريًا**. لا يملكه موظف الإدارة ولا المفتش. سبب القاعدة: الإيقاف يقيّد حق دخول شخص إلى مسكنه — قرار ذو أثر قانوني، ويجب أن يُسند إلى شخص محدد بالاسم في السجل.

## 4. قواعد الحوكمة العرضية

| القاعدة | النص | الأثر |
|---|---|---|
| `BR-041` | كل إجراء يكتب `actorId` = الفاعل الحقيقي، لا دورًا مفترضًا | يمنع `DEF-006` |
| `BR-042` | فصل الواجبات: من ينفّذ لا يعتمد | الحارس يكتب المحضر، المشرف يعتمده |
| `BR-043` | القرارات ذات الأثر القانوني تتطلب `⚠️` اعتمادًا ثانيًا | الإيقاف، التجاوز اليدوي، رفع الإيقاف |
| `BR-044` | لا صلاحية ضمنية بالوراثة | `district_manager` لا يرث `guard`؛ كل صلاحية صريحة |
| `BR-046` | الصلاحية تُفحص عند **الإجراء** لا عند **العرض** فقط | إخفاء الزر ليس حماية |
| `BR-047` | كل رفض صلاحية يُسجَّل في التدقيق كمحاولة | نمط `rejectIfLocked` نفسه معمَّم |

## 5. نموذج التنفيذ المقترح

```ts
// src/lib/permissions.ts — النموذج الهدف
export type Permission =
  | 'violation.suspend_vehicle'
  | 'mahdar.approve_and_lock'
  | 'settings.edit_ladder'
  | /* … 58 صلاحية */;

const ROLE_GRANTS: Record<Person['role'], Permission[]> = { /* المصفوفة أعلاه */ };

export const can = (actor: Person, p: Permission) =>
  ROLE_GRANTS[actor.role]?.includes(p) ?? false;

/** يُستدعى داخل الـslice قبل أي طفرة — لا في المكوّن */
export function assertCan(s: Store, p: Permission) {
  const actor = s.people.find(x => x.id === currentActor(s));
  if (!actor || !can(actor, p)) throw new PermissionDenied(p, actor?.role);
}
```

**نقطة الإلزام:** داخل الـslice قبل الطفرة، لا في المكوّن. إخفاء الزر تجربة مستخدم؛ رمي الاستثناء هو الأمان.

## 6. ما نُفّذ في هذه النسخة

| البند | الحالة |
|---|---|
| توثيق المصفوفة الكاملة (58 صلاحية × 10 أدوار) | ✅ منجز — هذا المستند |
| فصل الشخصية عن الدور مفاهيميًا | ✅ منجز |
| إسناد قرار الإيقاف للفاعل الحقيقي بدل «أول مشرف» | ✅ منفّذ في الكود |
| إضافة دور `district_manager` وتقييد الإعدادات | ✅ موثّق · ⏳ التنفيذ في `TSK-142` |
| طبقة `can()` / `assertCan()` النافذة | ⏳ موثّقة بالكامل — تنفيذها يتطلب مصادقة حقيقية (خارج النطاق) |
| مسار التجاوز اليدوي بقرار مشرف | ✅ منفّذ — `US-078` |
