## 1. خريطة النفوذ والاهتمام

```
عالي │  السفارات              جهة تشغيل الحي ★
النفوذ│  الجهة التنظيمية        إدارة الأمن ★
     │                        ──────────────
     │  المنشآت التجارية        السكان ★
منخفض│  الزوار                 المقاولون
     └────────────────────────────────────
        منخفض الاهتمام      عالي الاهتمام

★ = مستخدم مباشر للنظام
```

| الطرف | النفوذ | الاهتمام | استراتيجية التعامل |
|---|---|---|---|
| جهة تشغيل الحي | عالٍ | عالٍ | **يُدار عن قرب** — العميل الدافع وصاحب القرار |
| إدارة الأمن | عالٍ | عالٍ | **يُدار عن قرب** — المستخدم الأكثف والأكثر حساسية |
| السكان | منخفض فرديًا / عالٍ جماعيًا | عالٍ | **يُبقى راضيًا** — رضاهم مقياس نجاح معلن |
| السفارات | عالٍ | متوسط | **يُبقى راضيًا** — احتكاك واحد يصعد سياسيًا |
| الجهة التنظيمية | عالٍ | منخفض | **يُبقى مطّلعًا** — قابلية التدقيق تكفيه |
| المقاولون | منخفض | عالٍ | **يُبقى مطّلعًا** — مؤشرات أدائهم معروضة |
| المنشآت التجارية | منخفض | متوسط | **يُراقَب** — مصدر إيراد لا مستخدم أساسي |
| الزوار | منخفض | منخفض | **يُراقَب** — تجربة عابرة، بلا حساب |

## 2. الشخصيات التفصيلية

### 2.1 عبدالله — المقيم المالك

> «ضيفي واقف عند البوابة وأنا في اجتماع. لا أريد مكالمة، أريد أن يدخل.»

| | |
|---|---|
| **العمر · الدور** | 44 · مالك فيلا، أب لثلاثة، يعمل في القطاع الخاص |
| **الجهاز** | iPhone · عمودي · بيد واحدة · غالبًا وهو يمشي |
| **التردد** | 2–5 مرات أسبوعيًا، كلها مدفوعة بحاجة أو إشعار |
| **الكفاءة الرقمية** | عالية للتطبيقات الاستهلاكية · صفر صبر للنماذج الحكومية |
| **أهدافه** | تصريح في أقل من دقيقة · بلاغ يُغلق بإثبات · معرفة حالة مركباته |
| **إحباطاته** | نموذج بعشرة حقول لتصريح زائر · بلاغ «مغلق» بلا صورة · إشعار بلا رابط |
| **يقيس النجاح بـ** | «لم أتصل بأحد هذا الشهر» |
| **أثره على التصميم** | نموذج التصريح ديناميكي (حقول النوع فقط) · صور قبل/بعد إلزامية للإغلاق · كل إشعار برابط عميق |

### 2.2 نورة — موظفة الإدارة

> «عندي أربعون بلاغًا هذا الصباح. أريد أن أعرف أيها ينفجر أولًا.»

| | |
|---|---|
| **العمر · الدور** | 31 · موظفة تشغيل، تدير طوابير البلاغات والتصاريح |
| **الجهاز** | شاشة مكتبية 27" · لوحة مفاتيح · نوافذ متعددة |
| **التردد** | 8 ساعات يوميًا. هذا سطح مكتبها |
| **الكفاءة الرقمية** | عالية · تحفظ الاختصارات · تكره النقرات الزائدة |
| **أهدافها** | تصريف الطابور بالأولوية · قرار بضغطة · لوحة تقول ما العمل لا ما حدث |
| **إحباطاتها** | البحث اليدوي · إجراء بلا أثر مرئي · مؤشر بلا سياق («40 بلاغًا» — أكثر أم أقل من الأسبوع الماضي؟) |
| **تقيس النجاح بـ** | «صرّفت الطابور قبل الغداء» |
| **أثره على التصميم** | تخطيط قائمة/تفصيل بجانبين · دلتا مقارنة بالفترة السابقة على كل مؤشر · بطاقات المؤشرات تنقر للطابور المعني · SLA بارز |

### 2.3 فهد — حارس البوابة

> «السائق ينتظر. الشاشة إما تقول نعم أو لا. لا أريد أن أقرأ.»

| | |
|---|---|
| **العمر · الدور** | 27 · حارس البوابة الرئيسية، وردية 12 ساعة |
| **الجهاز** | جهاز لوحي 10" مثبّت · يُستخدم بيد واحدة · شمس نهارًا وظلام ليلًا |
| **التردد** | كل دقيقتين طوال الوردية |
| **الكفاءة الرقمية** | متوسطة · تدريب محدود · دوران وظيفي عالٍ |
| **أهدافه** | قرار واضح فورًا · إدخال سريع · ألا يُلام على قرار |
| **إحباطاته** | ألوان متقاربة · نص صغير · شاشة تحتاج تفسيرًا · مسؤولية بلا سند مكتوب |
| **يقيس النجاح بـ** | «نظرت فعرفت» |
| **أثره على التصميم** | **لوحة قرار ملء الشاشة، 64px أيقونة، 40px عنوان، تباين ≥ 7:1** · كل مسح يُسجَّل تلقائيًا (يحمي الحارس) · لا رسوم متحركة مكلفة · مساحات لمس ≥ 48px |

### 2.4 سلطان — مشرف الأمن

> «إن وقّعت على قرار، أريد أن يظهر اسمي عليه — وأن يبقى.»

| | |
|---|---|
| **العمر · الدور** | 39 · مشرف أمن، يقرّر ما لا يقرّره الحارس |
| **الجهاز** | لوحي + شاشة غرفة العمليات |
| **التردد** | مستمر، بتركيز متقطع |
| **الكفاءة الرقمية** | متوسطة-عالية · خبرة تشغيلية عميقة |
| **أهدافه** | صورة كاملة لحظية · قرار موثّق يحميه · سجل لا يُعدَّل بعده |
| **إحباطاته** | قرار بلا أثر · محضر يمكن تعديله بعد التوقيع · لا يعرف من غيّر ماذا |
| **يقيس النجاح بـ** | «السجل يحمي فريقي» |
| **أثره على التصميم** | **قفل المحضر ببصمة تحقق** · درج تدقيق على كل كيان حساس · اسم المقرِّر بارز في لوحة الرفض · محاولات التعديل المرفوضة مرئية |

### 2.5 د. أمل — مديرة الحي *(دور مضاف)*

> «لا أريد أن يغيّر موظف إدخال بيانات سياسة العقوبات في الحي.»

| | |
|---|---|
| **الدور** | مديرة التشغيل — تملك قواعد العمل لا الحالات |
| **التردد** | أسبوعيًا · تعديل سياسة، مراجعة اتجاه |
| **أهدافها** | ضبط السياسة بلا مطوّر · رؤية أثر التعديل فورًا · حصر صلاحية التغيير |
| **أثره على التصميم** | **سلّم التصعيد بيانات لا كود** · جدول SLA يقود السلوك فعلًا · صلاحية `settings.*` محصورة بدورها (`GAP-03`) |

### 2.6 راج — زائر السفارة

> «لا أعرف الحي، ولا أتكلم العربية جيدًا، ومعي موعد.»

| | |
|---|---|
| **الدور** | زائر لأمر قنصلي · مرة واحدة غالبًا · بلا حساب |
| **الجهاز** | هاتف Android متوسط · اتصال ضعيف |
| **أهدافه** | حجز موعد · دخول بلا احتكاك |
| **إحباطاته** | صف طويل · «الحد اليومي مكتمل» عند البوابة لا عند الحجز · رابط لا يفتح |
| **أثره على التصميم** | **رابط عام بلا تسجيل** لكل سفارة · رفض الحجز عند الامتلاء وقت الحجز لا وقت الوصول · رمز واحد يفتح البوابة |

## 3. جدول تأثير الشخصيات على القرارات

| القرار | الشخصية المحرّكة | البديل المرفوض ولماذا |
|---|---|---|
| ثيم داكن للأمن، فاتح للإدارة والمقيم | فهد، سلطان | ثيم موحّد — يفقد التوجيه الفوري «أين أنا»، ويرهق العين ليلًا |
| لوحة قرار ملء الشاشة عند البوابة | فهد | بطاقة نتيجة — تُقرأ لا تُلمح، وتفشل من 3 أمتار |
| صور «بعد» شرط الإغلاق | عبدالله | إغلاق بالثقة — يهدم مصداقية النظام كله |
| قفل المحضر نهائي بلا استثناء | سلطان | «فتح بصلاحية عليا» — يُبطل قيمة القفل ويحوّله لعرف اجتماعي |
| سلّم التصعيد من الإعدادات | د. أمل | ثابت في الكود — كل تعديل سياسة يصبح إصدارًا برمجيًا |
| رابط سفارة عام بلا تسجيل | راج | حساب زائر — احتكاك يقتل الاستخدام لزيارة واحدة |
| حد أقصى للتصاريح النشطة | نورة | بلا حد — طابور اعتمادات لا ينتهي |
