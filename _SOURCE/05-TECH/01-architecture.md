## 2. المبادئ المعمارية

### A1 · حقيقة واحدة، لا اشتقاق مكرر
`vehicle.accessState` هي **الحقيقة الوحيدة** لأهلية الدخول. سلّم التصعيد يكتبها، والبوابة تقرأها. لا تعيد البوابة اشتقاق أي قاعدة.

هذا ليس تفصيلًا — هو **الادعاء المعماري للمنتج**. لو أعادت البوابة الاشتقاق لصار لدينا نسختان من القاعدة تتباعدان مع الوقت، ولانهارت قابلية التدقيق.

### A2 · المنطق النقي منفصل عن الحالة
`lib/rules.ts` **دوال نقية**: تستقبل بيانات وتُرجع قرارات، بلا وصول للمخزن ولا آثار جانبية. هذا يجعلها قابلة للاختبار وحدويًا وقابلة للنقل إلى خادم لاحقًا.

```ts
evaluateGate(input, { vehicles, permits, properties, … }) → GateDecision
assertTransition(entity, map, from, to) → void | throws
```

### A3 · كل طفرة تكتب في التدقيق
كل شريحة تستدعي `appendAudit()` بلا استثناء واحد. تحقّقنا من الشرائح الإحدى عشرة — **الالتزام كامل**، وهذا من أقوى ما في القاعدة الحالية.

### A4 · الانتقالات غير القانونية ترمي
`assertTransition` يرمي `IllegalTransition` ولا ينفّذ جزئيًا.
> **الخرق المكتشف:** `approveMahdar` يقفز إلى `closed` متجاوزًا الآلة، و`requests` بلا آلة أصلًا (`DEF-010` · `DEF-019`).

### A5 · الشرائح لا تعرف بعضها إلا عبر `get()`
لا استيراد بين الشرائح. التواصل عبر الواجهة الموحّدة `Store`.

### A6 · التحميل الكسول للثقيل
`three.js` + `drei` + `three-mesh-bvh` (~1.2 ميغابايت) خارج الحزمة الأساسية، تُحمَّل عند فتح التوأم الرقمي فقط. **منفّذ ومصمَّم جيدًا.**

## 3. طبقة المخزن

### التركيب
```ts
export const useStore = create<Store>()((set, get) => ({
  ...buildSeed(),          // الحالة الابتدائية
  audit: [], persona: 'resident', toasts: [], demoSpeed: 1,
  setPersona, pushToast, dismissToast,
  appendAudit,             // عرضية
  notify, markAllRead, markRead,
  ...createPermitsSlice(set, get),
  ...createRequestsSlice(set, get),
  /* … 9 شرائح أخرى */
}));
```

### نمط الشريحة الموحّد
```ts
export const createXSlice = (set: Set, get: Get) => ({
  doThing: (id: ID, input: Input) => {
    const s = get();
    const entity = s.things.find(t => t.id === id);
    if (!entity) return;

    assertTransition('thing', thingTransitions, entity.status, 'next');   // 1 الحراسة
    set(st => ({ things: updateById(st.things, id, patch) }));            // 2 الطفرة
    get().appendAudit('thing', id, 'update', before, after);              // 3 التدقيق
    get().notify(target, title, body, deepLink, severity);                // 4 الإشعار
    get().pushToast(title, body, tone);                                   // 5 التغذية الراجعة
  },
});
```

**الترتيب مُلزم:** حراسة ← طفرة ← تدقيق ← إشعار ← توست. أي شريحة تخالفه تُعتبر خطأ في المراجعة.

### المرافق
```ts
currentActor(s)                    // الفاعل الحقيقي — BR-002
updateById(arr, id, patch)         // تحديث غير متحوّل، يقبل دالة أو كائنًا
```

## 4. طبقة العرض

### تسلسل التوجيه
```
createBrowserRouter
├── /                    → إعادة توجيه إلى /r
├── /book/:embassyId     → عام، بلا غلاف
├── /visit               → عام، بلا غلاف
├── /r  → PersonaShell('resident') → 11 شاشة
├── /a  → PersonaShell('admin')    → 14 شاشة
└── /s  → PersonaShell('security', dark) → 12 شاشة
```

`PersonaShell` يوحّد: الشريط العلوي · الشريط الجانبي · الثيم · الجرس · مبدّل الشخصية · مبدّل السرعة.

### 🔴 مشكلة الأداء المكتشفة — `DEF-035`

```ts
const store = useStore();   // ← بلا محدِّد
```

**19 مكوّنًا** يشتركون في المخزن كاملًا. النتيجة: **كل مكوّن يُعاد رسمه عند كل تغيير في أي جزء من الحالة** — ومع مؤقّت المستشعرات كل 3 ثوانٍ (ومئات المرات في وضع 10×) هذا يعني إعادة رسم مستمرة لكل شاشة مفتوحة.

**والتعليق في المصدر يحذّر منه:**
```ts
/** NOTE: derived arrays must be memoized in components (zustand snapshot identity) —
 *  never `useStore((s) => s.x.filter(...))` directly. */
```
التحذير موجود، والالتزام به غائب.

**الحل:**
```ts
// ❌
const store = useStore();

// ✅ محدِّدات ذرّية
const violations = useStore(s => s.violations);
const escalate  = useStore(s => s.escalateViolation);

// ✅ المشتقات في useMemo
const open = useMemo(() => violations.filter(v => v.status !== 'closed'), [violations]);
```

## 7. الاختبار — الغائب الأكبر

**لا يوجد اختبار واحد في المشروع.** لا وحدوي ولا تكاملي ولا شامل.

### الحد الأدنى المقترح

```
lib/rules.test.ts          ← الأولوية القصوى: evaluateGate + كل آلة حالة
store/slices/*.test.ts     ← كل شريحة: الحراسة والطفرة والتدقيق
lib/time.test.ts           ← withinWindow · isPast · daysFromNow
```

**الأولوية المطلقة:** `evaluateGate()`. هي أخطر دالة في المنتج، وثلاثة من عيوب P0 كانت فيها. اختبار وحدوي واحد لكل مسار من مساراتها الستة كان سيمنعها جميعًا.

## 8. مسار الترقية إلى إنتاج حقيقي

```
اليوم                      الإنتاج
──────────────────────────────────────────────────────
Zustand في الذاكرة   →   Zustand + استعلامات API
buildSeed()          →   بذرة قاعدة بيانات
lib/rules.ts نقي     →   نفسه، يعمل على الخادم أيضًا ✅
appendAudit()        →   جدول تدقيق ملحَق فقط
notify()             →   طابور إشعارات + push
مبدّل الشخصيات       →   مصادقة + JWT بالأدوار
can() موثّقة         →   وسيط صلاحيات نافذ
```

**نقطة القوة:** `lib/rules.ts` نقي بالكامل — **ينتقل إلى الخادم بلا تعديل سطر واحد**. هذا أفضل قرار معماري في المشروع، ويعني أن قواعد العمل لن تُكتب مرتين.
